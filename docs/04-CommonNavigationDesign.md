# StageArt BluePrint

## 04. 全画面共通ナビゲーション設計

### 1. 基本方針
StageArtのHomeは「機能一覧」ではなく、そのユーザーが現在必要としている情報・操作への入口とする。

一方、全画面から主要機能へ移動できる共通ナビゲーションを設け、iPad等のスワイプ操作に依存しない。

ナビゲーションは以下の3層で構成する。

1. Bottom Navigation（主要画面への常設入口）
2. Screen Header Navigation（戻る操作）
3. Context Navigation（現在の団体・公演コンテキストの明示）

---

## 2. Bottom Navigation

全ユーザー共通で以下の4項目を常設する。

- Home
- 探す
- お気に入り
- マイページ

### 2.1 Home
ユーザーの権限・所属・現在必要な操作に応じて内容を動的に表示する。

Homeに表示する詳細は「Home Role-Based Menu and Management Entry Design」に従う。

### 2.2 探す
「探す」画面から以下へ進む。

- 団体を探す
- 公演・活動を探す

これらはHomeにも必要に応じて入口を表示してよいが、Bottom Navigationの「探す」から常にアクセス可能とする。

### 2.3 お気に入り
ユーザーのお気に入りを集約する。

最低限、以下の分類を持つ。

- お気に入りの団体
- お気に入りの公演・活動

### 2.4 マイページ
個人設定・プロフィール関連の入口とする。

初期項目は以下。

- プロフィール
- ユーザ名変更
- SNS連携
- 団体・公演に参加
  - 招待Key入力
  - QRコード読み取り
  - 団体検索
  - 公演・活動検索
- その他設定
- ログアウト

設定・ログアウトはHomeの主要コンテンツではなく、マイページ側に集約する。

---

## 3. Screen Header Navigation（戻るボタン）

### 3.1 原則
Bottom Navigationの4画面そのもの以外は、Navigation Stackを持つ画面として扱い、原則として画面左上に明示的な戻るボタンを表示する。

ユーザーがスワイプ操作を覚えていることを前提としない。

例：

Home → 団体情報 → メンバー管理

の場合、メンバー管理画面には「← 団体情報」、団体情報画面には「← Home」等、直前のNavigation Contextに沿った戻る操作を提供する。

### 3.2 Bottom Navigation画面
Bottom Navigationで直接切り替えた以下の画面では、通常の「戻る」ボタンは不要とする。

- Home
- 探す
- お気に入り
- マイページ

---

## 4. Context Navigation

StageArtではユーザーが複数の団体・複数の公演に所属することを前提とする。

そのため、団体・公演に関する詳細画面では、現在どのコンテキストを操作しているかをユーザーが常に識別できるようにする。

例：

- 劇団StageArt
- 「12人のうかれる人々」

公演管理、稽古管理、会計管理等では、対象となる団体・公演が分かるHeaderまたはContext表示を設ける。

通知、稽古予定、出欠確認等についても、複数所属時にどの団体・公演に属する情報なのかを必ず識別可能とする。

---

## 5. 管理機能の配置

団体管理・公演管理機能はBottom Navigationの固定項目には追加しない。

理由：一般観客には不要な管理機能を常時表示しないため。

管理機能は所属コンテキストから進む。

例：

Home → 所属団体 → 団体管理

Home → 参加中の公演・活動 → 公演・活動管理

管理者向けのHome表示は、必要な管理操作へのショートカットとして扱う。

---

## 6. 所属コンテキストとHome

Homeでは、所属している団体・参加している公演・活動がある場合のみ、そのコンテキストへの入口を表示する。

一般ユーザーに対して「どこにも所属していません」等の状態を強調表示しない。

予定が存在しない場合も「次回稽古なし」等の不要な空状態を常時表示しない。

必要な情報・操作が存在する場合にのみHomeへ表示する。

---

## 7. 確定事項

- 全ユーザー共通のBottom Navigationは4項目
  - Home
  - 探す
  - お気に入り
  - マイページ
- 設定・ログアウトはマイページに集約
- Bottom Navigation以外の階層画面には原則として明示的な戻るボタンを表示
- スワイプ操作のみを戻る手段にしない
- 団体・公演の操作画面では現在のContextを常に識別可能にする
- 複数団体・複数公演への所属を前提とする
- 管理機能はBottom Navigationへ固定表示しない
- Homeは「機能一覧」ではなく「現在必要な情報・操作への入口」とする
