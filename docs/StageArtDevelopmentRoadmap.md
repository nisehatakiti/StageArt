## 1. このロードマップの目的

StageArtを一つの舞台芸術活動プラットフォームとして完成させるため、個別機能の開発に偏らず、全機能の状態・依存関係・優先順位を一元管理する。

StageArtの完成像は、団体の設立・メンバー管理から、公演企画、制作、稽古、チケット販売、予約・受付、会計・精算、活動履歴、広報までを一貫して支援すること。

個別タスクを開始する前に必ず本書を確認し、対象機能・全体フェーズ・依存関係を明記する。タスク完了時には本書を更新する。

## 2. ステータス定義と判定ルール

機能の状態と、実装レイヤーの状態を混同しない。コードが存在するだけでは完了としない。

### 2.1 機能ごとの状態（2026-11-25から使用）

| 状態 | 意味 |
|---|---|
| **実装済み** | 開発ブランチ（`feature/user-account-identity`）にコードがある |
| **テスト済み** | 自動テスト（PHPUnit・jest）が開発ブランチで通っている |
| **Dev配置済み** | そのコードが Dev（dev.stageart.top / dev-api.stageart.top）に配置されている |
| **Dev動作確認済み** | Dev上で実際に操作して期待どおり動くことを確認した。**API** で確認したか **画面** で確認したかを必ず書き分ける |
| **未実装** | 開発ブランチにコードがない |
| **未統合** | コードは別ブランチ・退避ブランチ・旧リポジトリにあるが、開発ブランチに入っていない |
| **要修正** | 仕様と異なる動作、または不具合を確認した |
| **仕様未確定** | 仕様の判断待ちで、実装・検証の基準が決まっていない |

一つの機能に複数の状態が付くことがある（例：「実装済み・テスト済み・Dev配置済み・Dev動作確認済み（API）・画面未確認」）。

### 2.2 総合判定（領域単位）

| 総合判定 | 意味 |
|---|---|
| **完成** | §9の完成判定基準をすべて満たす |
| **Dev確認中** | Dev配置済みで、Dev動作確認が一部完了 |
| **実装済み・未検証** | コードはあるが、Devでの確認が不足 |
| **開発中** | 実装または検証が進行中 |
| **仕様確定・未着手** | 仕様はあるが実装なし |
| **設計中／構想段階** | 仕様が未確定 |
| **要調査** | 状態を断定できる根拠がない |

**注意**: 「Blueprintに記載がある」ことは「実装済み」を意味しない。「テストが通る」ことは「Devに配置済み」を意味しない。「APIで確認した」ことは「画面で確認した」ことを意味しない。旧リポジトリやDevの退避コードに機能があることは「開発ブランチに統合済み」を意味しない。

## 3. 全体サマリー（2026-11-25時点）

### 3.1 現在地

- 開発ブランチ `feature/user-account-identity` = `c45688f`（PR #9：公演権限の整理をマージ）。PHPUnit 2,518件合格（2 skipped）、jest 642/647（既知の失敗5件はc45688f以前から）。
- **Dev は 2026-11-25 に c45688f へ更新済み**（APIプラグイン・画面とも。DB schema 1.44.0 → 1.48.0）。それまでDevは未コミットの作業ツリー由来のコードで動いていた。
